# MiniMax TTS 语气与停顿控制研究

> 目标：dry/smoke 阶段继续使用现有微软 Edge TTS；正式阶段评估 MiniMax `speech-2.8-hd`。本文只记录接口能力与建议映射，不改运行时行为。

## 一、结论

- MiniMax `speech-2.8-hd` **不是标准 SSML**。它采用自有标记加结构化参数：
  - 全局情绪放在 `voice_setting.emotion`；
  - 自定义停顿插入在合成文本中，格式是 `<#秒#>`；
  - 语气词直接以英文括号标签写入文本，例如 `(laughs)`；
  - 发音修正使用 `pronunciation_dict.tone` 或行内小括号拼音/IPA。
- `speech-2.8-hd` / `speech-2.8-turbo` 支持语气词标签；旧模型不一定支持。
- API 地址为 `https://api.minimaxi.com/v1/t2a_v2`，认证方式是 HTTP Bearer Token。
- 单次请求文本限制小于 10000 字符；超过 3000 字符官方推荐流式输出。本项目逐句调用通常远低于该阈值，仍应保留逐句产物。

## 二、基础请求结构

```json
{
  "model": "speech-2.8-hd",
  "text": "消息传开，营地里炸开了锅。<#0.35#>有人收拾行李，有人骂骂咧咧。(breath)只有守夜的老猎人蹲在火堆旁。",
  "stream": false,
  "voice_setting": {
    "voice_id": "候选音色待定",
    "speed": 1.0,
    "vol": 1.0,
    "pitch": 0,
    "emotion": "calm"
  },
  "audio_setting": {
    "sample_rate": 32000,
    "bitrate": 128000,
    "format": "mp3",
    "channel": 1
  },
  "subtitle_enable": true,
  "subtitle_type": "word"
}
```

返回的非流式音频默认是 hex 编码字符串；解码后建议先用 ffmpeg 统一转为 48kHz 单声道 WAV，再交给现有渲染器。

## 三、停顿控制

### 标记规则

| 规则 | 说明 |
| --- | --- |
| 格式 | `<#x#>` |
| 取值 | `0.01 <= x <= 99.99` 秒，最多两位小数 |
| 插入位置 | 必须夹在两段可发音文本之间 |
| 连续性 | 不能连续放多个停顿标记 |
| 段落 | 官方另支持换行符表示段落切换 |

### 建议映射

当前解说稿已经是逐句结构。每一句的句间关系可以由 LLM 或确定性规则标注为暂停级别：

| 叙事场景 | 文本到 MiniMax 停顿 | 其他参数 |
| --- | --- | --- |
| 同段落普通推进 | 逗号自然处理；句子内部一般不加标记 | 全局 `speed` + 默认 `emotion` |
| 句号后继续讲 | 下一句开头前 `<#0.25#>` 到 `<#0.4#>` | 保持 calm |
| 关键转折前的蓄力 | 冒号/转折词前 `<#0.4#>` 到 `<#0.7#>` | 可改为 `surprised` 或降低局部速度 |
| 身份揭露后的留白 | 结论句后 `<#0.5#>` 到 `<#0.9#>` | 保持或改回 calm |
| 危险/悬疑收束 | 转折词前后 `<#0.35#>` 到 `<#0.6#>` | 局部降速比提高音量更符合当前风格目标 |
| 进入原声保留段前 | 下一解说片段开头前 `<#0.2#>` 到 `<#0.35#>` | 让听感从原声切回旁白更平滑 |

注意：现有 EDL 已经会让每个解说片段之间天然相邻。加了过长的显式停顿会推高真实音频时长，进一步触发画面裁剪或末帧冻结；因此正式接入时应先做短清单试听，而不是默认全局加停顿。

## 四、语气与情绪控制

### 1. 全局情绪参数

`voice_setting.emotion` 是主开关，支持值包括：

`happy`, `sad`, `angry`, `fearful`, `disgusted`, `surprised`, `calm`, `fluent`, `whisper`

但文档明确指出模型会按文本自动匹配合适情绪，通常无需手动指定；且 `speech-2.8-hd` / `speech-2.8-turbo` 不支持 `whisper`。对本项目的叙事人格，建议初期只用少数几档：

| 场景 | 建议 emotion |
| --- | --- |
| 默认 / 平稳复盘 | `calm` 或省略让模型自动判断 |
| 自然讲述、信息流动 | `fluent` |
| 发现线索、出现疑问 | 接口没有 curious；用 fluent 或 calm 承接 |
| 悬疑与转折 | `surprised` |
| 牺牲与遗憾 | `sad` |
| 高潮战斗 | 保持固定节奏，不建议主动改成 angry |

这里不需要写代码级枚举，先保留“calm/fluent/surprised/sad”四档即可，避免把表现层过早写死进配置。

### 2. 语气词标签

`speech-2.8-hd` 支持直接插入的小括号标记。可用于自然的叙述呼吸，但不宜频繁堆叠：

| 标签 | 含义 | 项目内适用场景 |
| --- | --- | --- |
| `(breath)` | 正常换气 | 较长解说句的中后段、镜头切换后重新开口 |
| `(sighs)` | 叹气 | 遗憾、牺牲、误会揭开的余韵 |
| `(chuckle)` | 轻笑 | 极少量的人物性格反差或幽默节点 |
| `(clear-throat)` | 清嗓子 | 几乎不用；可在片头后的第一句试用 |
| `(gasps)` | 倒吸气 | 关键反转揭示句，慎用 |
| `(emm)` | 嗯 | 一般不适合冷静故事旁白 |
| `(groans)` | 呻吟 | 不适合旁观式剧情复盘 |
| `(pant)` / `(inhale)` / `(exhale)` | 喘气/吸呼气 | 战斗或危险镜头后的特殊强调，应做 A/B 试听 |

示例：

```text
我们循着歌声走到崖边。<#0.45#>(breath)才发现整座小镇的人都聚在那里。
身份被揭露的那一刻，现场安静得过分。<#0.65#>(sighs)她只是低声说出了那个名字。
```

### 3. 行内发音替换

行内语法：把普通话拼音、IPA 或粤语拼音用英文小括号包住，临时覆盖多音字或专有名词。

```text
这里是 (li4)，不是重量的 (zhong4)。
```

对稳定出现的原神专有名词，优先放进 `pronunciation_dict.tone` 数组而不是每句正文里手工插标签。这样注释和校验更容易维护，也不会污染字幕文本。

## 五、候选音色

用户提供的两个候选如下，待试听后确定一个：

1. `Chinese_playful_streamer_nv1`
2. `Chinese (Mandarin)_IntellectualGirl`

公开的系统音色列表页没有展示这两个名称，因此接入前必须通过账户侧的可用音色查询或在控制台复制确切 ID 来复核。不要把它们当成已长期稳定的默认值写死。

对比维度沿用项目已有《短视频虚拟人语音风格筛选标准》：

- 成年女声、中低音区，避免幼态和主播腔；
- 连续朗读 2-3 分钟是否耐听；
- 平静、调查、反转、惋惜四种样稿是否成立；
- 人名与游戏专有名词读音是否稳定；
- 语速调整后是否会吞字、拖音或产生机械停顿。

## 六、接入建议

1. 配置层保持兼容：现有 `engine: edge` 作为 dry/smoke 验证路径；新增正式引擎时优先扩展 `stage_render.synthesize()` 分支，不让调用方感知供应商差异。
2. 请求结果统一转码：MiniMax 回传 mp3/hex 后转 48kHz mono WAV，再进入现有 ffmpeg 流程。
3. 保留句级 WAV：即使以后做批量或流式生成，也要拆回每个 `narration_clip` 对应的文件，否则画面裁剪、末帧冻结、剪映精修和字幕轴都会失去控制点。
4. 增加 dry/prose 双轨参数：dry 用 edge 保证低成本跑通；正式模式保存 provider/model/voice/emotion/语速，音色 ID 未确认前不允许进入生产渲染。
5. 表演指令与剪辑解耦：TTS 标签只能写在发送给服务器的 prompt text 中，不能污染 `narration.md`、SRT/ASS 字幕和剪映轨上的原始解说文本。
