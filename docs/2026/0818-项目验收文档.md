## 一、项目概述

**项目目标**：将几小时长视频剧情录像 + 准确台词文稿，自动浓缩为十几分钟的解说短视频。

**命令行入口**：`mmm`（mini-movie-maker 缩写），基于 typer 的 Python CLI。

**技术栈**：Python 3.11+ / ffmpeg / faster-whisper / difflib / SQLite / OpenAI 兼容 LLM 网关

**核心流水线**：7 个阶段顺序执行，阶段 1-4 逐视频处理，阶段 5-7 任务级处理。两个闸口（阶段5后审稿、阶段6后审片）需人工确认。

## 四、新发现的 BUG（v2 审查新增）

### BUG-1：stage_render.py 缺少 `import re` [P0] — ✅ 已修复

**位置**：`src/mmm/stage_render.py` 第 120 行

`_has_ass_filter()` 函数使用 `re.search()`，但文件头只有 `import json / subprocess / tempfile`，没有 `import re`。开启字幕 overlay 模式时（`_has_ass_filter()` 被调用），会抛 `NameError: name 're' is not defined`。

**影响**：字幕烧录功能完全不可用（overlay 模式直接崩溃）。

**修复**：文件头加 `import re`。✅ 已补，本机 ffmpeg 无 libass 走 SRT fallback 验证通过。

### BUG-2：BGM ducking 与字幕的时间轴错位 [P1] — ✅ 已修复

**位置**：`src/mmm/stage_render.py` `_bgm_duck_regions()` + `src/mmm/stage_subtitle.py` `build_subtitles()`

EDL clip 的 `start`/`end` 是**源视频内本地区间**（相对时间轴铁律，由 `stage_select.py` 的 `local_start = round(clip_start - off, 2)` 生成）。但 BGM ducking 和字幕烧录是在 concat 拼接**之后**执行的，需要的是**成片时间轴**（从 0 开始累加）。两者不匹配。

**影响**：
- BGM ducking 区域错位：narration/raw_insert 区间映射到错误的时间点，可能在不该压低时压低、该压低时没压
- 字幕时间错位：字幕显示时间与画面不对应，每句字幕偏移量 = 该片段之前所有片段时长之和

**当前影响范围**：MVP 所有片段都是 narration_clip 时，BGM 全程 ducking 影响不明显；但字幕时间轴一定是错的。有 raw_insert 时 BGM 也会出错。

**修复**：✅ `stage_subtitle._output_spans()` 与 `stage_render._bgm_duck_regions()` 均改为按成片时间轴累计（复用 `seg_durations` 渲染实测片段时长，含 TTS 冻结补齐）；`stage_render.run()` 在 concat 后传入实测时长。

### BUG-3：PROGRESS.md 未同步 [P3] — ✅ 已修复

PROGRESS.md 仍标注"阶段7打磨 🚧 进行中：待补云TTS/BGM/字幕/transform/片头"，但 BGM/字幕/transform/片头均已实现。✅ 已同步：阶段7打磨标完成、断点续跑标完成、导出器B 标完成。
